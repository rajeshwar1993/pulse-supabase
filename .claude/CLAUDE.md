## Coding Patterns & Conventions

**Migration File Naming**
- Format: `YYYYMMDDHHMMSS_description.sql`
- Generated by CLI: `supabase migration new <description>`
- Example: `20260215104737_create_connections_system.sql`

**Table Naming**
- Plural lowercase: `profiles`, `daily_pulses`, `connections`, `invite_codes`
- Use snake_case for multi-word tables and columns

**Column Conventions**
- Primary key: `id uuid primary key default gen_random_uuid()`
- Foreign keys: `{table}_id` (e.g., `user_id`, `connection_id`)
- Timestamps: `created_at timestamptz default now()`
- Soft delete: `deleted_at timestamptz` (nullable)

**Row Level Security (RLS)**
- Enable RLS on all tables: `alter table <table> enable row level security;`
- Policies named: `{table}_{action}_{description}` (e.g., `profiles_select_own_profile`)
- Use `auth.uid()` for current user ID
- Grant minimal permissions (select, insert, update, delete individually)

**SQL Style**
- Keywords: UPPERCASE (CREATE, SELECT, INSERT, ALTER)
- Identifiers: lowercase snake_case (table_name, column_name)
- Comments: `-- Description` for single line, `/* ... */` for blocks
- One statement per migration file (or related statements grouped logically)

## Integration Points

**pulse-supabase → pulse-app**
- Flutter app connects via `supabase_flutter` package
- Uses `SUPABASE_URL` and `SUPABASE_ANON_KEY` from `.env`
- Direct database access (inserts, selects, updates) via Supabase client
- RLS policies enforce data access control

**pulse-supabase → pulse-web**
- Next.js app connects via `@supabase/ssr` package
- SSR: Server client uses cookies for session management
- Browser: Client reads session from cookies
- Same RLS policies apply to both web and app

**Authentication**
- Supabase Auth handles user sign-up, login (email OTP, OAuth, etc.)
- User ID: `auth.uid()` (UUID from auth.users table)
- Profiles table: `id` references `auth.users.id` (foreign key)
- Session tokens: JWT stored in cookies (managed by Supabase SDKs)

## Common Code Patterns

**Create Table Migration**
```sql
-- File: 20260211162432_create_profiles_table.sql

create table profiles (
  id uuid primary key references auth.users(id) on delete cascade,
  display_name text not null,
  avatar_seed text not null,
  created_at timestamptz default now()
);

-- Enable RLS
alter table profiles enable row level security;

-- RLS Policies
create policy "Users can view their own profile"
  on profiles for select
  using (auth.uid() = id);

create policy "Users can insert their own profile"
  on profiles for insert
  with check (auth.uid() = id);

create policy "Users can update their own profile"
  on profiles for update
  using (auth.uid() = id);

-- Indexes
create index idx_profiles_created_at on profiles(created_at);
```

**RLS Policy Patterns**
```sql
-- Select own records
create policy "users_select_own"
  on table_name for select
  using (auth.uid() = user_id);

-- Insert with ownership check
create policy "users_insert_own"
  on table_name for insert
  with check (auth.uid() = user_id);

-- Update with ownership check
create policy "users_update_own"
  on table_name for update
  using (auth.uid() = user_id);

-- Delete with ownership check
create policy "users_delete_own"
  on table_name for delete
  using (auth.uid() = user_id);

-- Complex policy (e.g., view connections where you're either user)
create policy "connections_select_participating"
  on connections for select
  using (auth.uid() = user_id or auth.uid() = connected_user_id);
```

**Add Column Migration**
```sql
-- File: 20260216120000_add_profile_bio.sql

alter table profiles
  add column bio text;

-- Optional: set default for existing rows
update profiles set bio = '' where bio is null;
```

**Create Function and Trigger**
```sql
-- Auto-update updated_at timestamp
create or replace function update_updated_at_column()
returns trigger as $$
begin
  new.updated_at = now();
  return new;
end;
$$ language plpgsql;

create trigger set_updated_at
  before update on profiles
  for each row
  execute function update_updated_at_column();
```
